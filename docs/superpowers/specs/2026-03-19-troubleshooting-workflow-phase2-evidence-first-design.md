# 排障工作流 Phase 2 设计：证据优先收口

## 1. 目标

`Troubleshooting Workflow Phase 2` 的目标不是压制 agent 的判断能力，而是在调查尚未完全收敛时，为结果收口增加一个更稳的交互约束：

- 先列事实、证据、未确认点和下一步
- 在证据已经较强时，允许补充低置信度倾向
- 在用户未明确放行前，不把倾向表达成“根因已确认”

本阶段优先解决的问题是：

- 用户可以要求 agent 先按证据收口，而不是过早定性
- 该约束会显式落入会话状态，而不是依赖模型临时记忆
- 结果表达更稳，但调查推进和工具使用能力不被削弱

## 2. 核心原则

- 本项目的第一目标仍然是强大的排障能力
- 控制只能约束结果怎么收口，不替代调查判断
- 控制层保持轻量，不引入新的 workflow engine
- 允许给出低置信度倾向，但不允许在未放行前给出已确认根因式结论
- 不得绕过现有只读、审批、审计和范围确认边界

## 3. 范围

### 3.1 Phase 2 支持的能力

- 用户要求先给证据，再给判断
- 用户要求先不要急着下结论
- 会话级保持证据优先收口模式，直到用户显式解除
- 在该模式下，排障类结果回复优先呈现事实、证据、未确认点、下一步
- 当证据较强时，允许补充低置信度倾向

### 3.2 适用边界

`evidence_first` 只作用于排障调查的自然语言结果收口，不作为全局对话模式。

Phase 2 推荐作用范围：

- 调查中的阶段性结论
- 调查完成后的排障结论回复
- 调查过程中的阶段总结

Phase 2 明确不直接改写以下产物或流程：

- 普通非排障聊天
- `/new` 之类的会话控制命令
- inspection、report、case 的结构化正文生成流程
- 既有 pause、resume、多目标确认等流程控制回复

如果 inspection、report、case 需要体现该模式，Phase 2 只允许影响这些产物的摘要语气，不改动其结构化正文 schema。

### 3.3 Phase 2 不做的事情

- 不做调查计划编排器
- 不做证据打分系统或完整 proof engine
- 不做根因自动确认框架
- 不做复杂报告模板系统
- 不做新的修复执行门控

## 4. 控制模型

### 4.1 外部交互

控制输入采用双轨：

- 自然语言
  - `先别急着下结论`
  - `先给证据再说判断`
  - `先别定性`
- 固定短指令
  - `先证据后判断`

解除控制也采用自然语言和短指令：

- `直接说结论`
- `你可以下判断了`
- `直接给判断`

### 4.2 内部控制意图

Phase 2 推荐新增一个轻量结果收口意图：

- `result_mode`

Phase 2 先只支持一个模式值：

- `evidence_first`

解除时将该模式清空，而不是引入额外复杂状态机。

## 5. 会话状态设计

Phase 2 继续挂在现有会话状态和 `AgentLoop` 周边，不引入新的 workflow engine。

建议新增最少状态：

- `workflow_result_mode: str | None`
- `workflow_result_mode_reason: str | None`
- `workflow_last_control_input: str | None`

约束如下：

- `workflow_result_mode="evidence_first"`：后续结果收口优先走证据结构
- `workflow_result_mode_reason`：记录简短来源，便于回显和审计
- 用户显式放行后清空 `workflow_result_mode` 及其附属原因
- 不清空已有证据、不回滚已有调查上下文

## 6. 回复分级

`evidence_first` 模式只约束“怎么对用户表达”，不约束“怎么调查”。

### 6.1 默认收口结构

结果回复建议按以下顺序组织，允许缺省，但顺序尽量稳定：

- 已确认事实
- 关键证据
- 未确认点或风险点
- 下一步建议

### 6.2 低置信度倾向

当当前证据已经明显指向某个方向时，允许额外补一段 `当前倾向`，但必须采用降级措辞，例如：

- `当前更像是 ...`
- `现有证据更偏向 ...`
- `目前更怀疑 ...`

允许补充 `当前倾向` 的最低条件：

- 至少存在两条相互一致的证据线索，或一条强直接证据加一条辅助证据
- 当前未确认点不会直接推翻该倾向
- 倾向表达必须明确保留不确定性

若不满足以上条件，则只能输出证据、缺口和下一步，不补充倾向判断。

### 6.3 强结论限制

在用户未显式放行前：

- 不允许把判断表达成 `根因已确认`、`问题已经定位到`、`可以确定就是`
- 不允许省略未确认点，直接把怀疑对象写成最终结论
- 不允许把未验证前提上的修复建议表达成最终结论
- 如需建议动作，应表述为 `建议先验证 X，再决定是否执行 Y`

### 6.4 最低回复结构

当 `evidence_first` 生效且当前回复属于排障收口时，回复至少应满足以下结构要求：

- 至少出现一条 `已确认事实` 或 `关键证据`
- 至少出现一条 `未确认点` 或 `下一步建议`
- 如包含 `当前倾向`，该段必须位于证据之后

允许缺省标题，但不允许跳过证据层直接给结论层。

### 6.5 降级规则

当模型原始回复中同时包含证据和强结论时，输出层应按以下规则降级：

- 保留原有证据内容
- 将强结论改写为 `当前倾向` 风格表达
- 若原回复缺失未确认点，则补入简短未确认点或验证缺口
- 若原回复缺失下一步，则补入最小化下一步建议

允许示例：

- `当前更像是服务启动后持续重试导致的连接耗尽，但还需要再核对错误日志和连接数变化。`
- `现有证据更偏向 node-a 上的日志轮转异常，不过还不能当作已确认根因。`

禁止示例：

- `根因已确认，就是日志轮转失败。`
- `可以确定是 node-a 的服务配置错误。`
- `直接重启服务即可恢复。`

## 7. Loop 接入

Phase 2 的接入点应放在“自然语言结果输出”层，而不是工具调用层。

### 7.1 控制识别层

- 识别进入 `evidence_first` 模式的表达
- 识别解除 `evidence_first` 模式的表达
- 将控制写入 session metadata

### 7.2 运行时上下文层

- 在构建回复上下文时注入当前为 `evidence_first` 模式
- 明确该模式只影响结果收口，不影响调查动作选择

### 7.3 输出约束层

- 在生成阶段总结、调查结论或最终自然语言回复前检查 `workflow_result_mode`
- 当模式为 `evidence_first` 时，优先按证据结构收口
- 若出现强结论措辞，则降级成 `当前倾向`

### 7.4 控制优先级

`evidence_first` 属于结果收口控制，优先级低于现有会话和调查流程控制。

推荐优先级顺序：

1. 会话级硬控制
   - `/new`
   - session reset 类控制
2. 已有调查流程控制
   - pending target expansion confirmation
   - `pause` / `resume`
   - `change_focus` / `narrow_scope`
3. 结果收口控制
   - 进入 `evidence_first`
   - 解除 `evidence_first`
4. 普通排障意图

约束如下：

- 如果当前消息命中 `/new` 或其他会话级硬控制，`evidence_first` 不参与处理
- 如果当前消息用于响应 pending target expansion gate，则先消费该 gate，不把该消息再解释成结果收口控制
- 如果当前会话处于 paused，且用户消息是 `继续`，先恢复调查，不额外改写结果模式
- `evidence_first` 只在正常排障消息和排障控制消息路径里识别
- 同一条消息如果同时命中 `change_focus` 或 `narrow_scope` 与 `evidence_first`，优先保留调查控制，结果收口控制不叠加生效

## 8. 用户体验

控制反馈继续保持“驾驶舱确认”风格，而不是长篇聊天解释。

### 8.1 控制确认

示例：

- `后续先按证据收口；如果判断还不够稳，我会先列证据和未确认点。`
- `当前先不给定性结论；若证据已较强，我会补充一个低置信度倾向。`

### 8.2 解除确认

示例：

- `已解除证据优先收口；后续可直接给出判断。`

### 8.3 控制后的调查衔接

示例：

- `调查方式不变；我只会把结果先按证据和未确认点收口。`
- `如果现有证据已经足够强，我会补充当前倾向，但不会直接当作已确认根因。`

## 9. 测试边界

Phase 2 至少需要覆盖以下行为：

- `先别急着下结论`、`先给证据再说判断` 能识别成 `evidence_first`
- `直接说结论`、`你可以下判断了` 能解除该模式
- 模式写入 session metadata，后续 turn 继续生效
- 解除后状态被清除，不影响其他 workflow 控制
- 开启 `evidence_first` 后，调查工具选择和调查推进不应被截断
- `evidence_first` 下，回复优先呈现事实、证据、未确认点、下一步
- 当模型想输出强结论时，应被降级为 `当前倾向`
- `当前倾向` 只能出现在证据之后，且必须保留不确定性措辞
- 原始回复缺少未确认点或下一步时，输出层会补齐最小结构
- 普通聊天或普通排障请求不能被误识别为结果收口控制
- `/new`、pending target expansion、pause/resume 等已有控制优先级不被破坏
- inspection、report、case 的结构化正文流程不应被改写

## 10. 非目标

本阶段明确不做：

- 证据置信度评分模型
- 任意结果模板编排器
- 新的报告产物工作流
- 结论审批系统
- 自动修复闭环

## 11. 推荐结论

Phase 2 推荐采用“证据优先的软门控收口模式”。

即：

- 新增轻量 `result_mode=evidence_first`
- 只约束结果收口，不限制调查动作
- 允许给低置信度倾向，但不允许在未放行前给出已确认根因式结论
- 继续沿用最小状态、最小侵入、最小行为面的设计原则

这样可以在不削弱排障能力的前提下，降低过早定性的风险，并为后续更强的结果产物化能力预留接口。
