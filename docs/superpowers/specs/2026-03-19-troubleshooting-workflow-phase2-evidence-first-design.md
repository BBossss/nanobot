# 排障工作流 Phase 2 设计：证据优先收口

## 1. 目标

`Troubleshooting Workflow Phase 2` 的目标不是压制 agent 的判断能力，而是在调查尚未完全收敛时，为结果收口增加一个更稳的交互约束：

- 先列事实、证据、未确认点和下一步
- 在证据已经较强时，允许补充低置信度倾向
- 在用户未明确放行前，不把倾向表达成“根因已确认”

本阶段优先解决的问题是：

- 用户可以要求 agent 先按证据收口，而不是过早定性
- 该约束会显式落入会话状态，而不是依赖模型临时记忆
- 结果表达更稳，但调查推进和工具使用能力不被削弱

## 2. 核心原则

- 本项目的第一目标仍然是强大的排障能力
- 控制只能约束结果怎么收口，不替代调查判断
- 控制层保持轻量，不引入新的 workflow engine
- 允许给出低置信度倾向，但不允许在未放行前给出已确认根因式结论
- 不得绕过现有只读、审批、审计和范围确认边界

## 3. 范围

### 3.1 Phase 2 支持的能力

- 用户要求先给证据，再给判断
- 用户要求先不要急着下结论
- 会话级保持证据优先收口模式，直到用户显式解除
- 在该模式下，结果回复优先呈现事实、证据、未确认点、下一步
- 当证据较强时，允许补充低置信度倾向

### 3.2 Phase 2 不做的事情

- 不做调查计划编排器
- 不做证据打分系统或完整 proof engine
- 不做根因自动确认框架
- 不做复杂报告模板系统
- 不做新的修复执行门控

## 4. 控制模型

### 4.1 外部交互

控制输入采用双轨：

- 自然语言
  - `先别急着下结论`
  - `先给证据再说判断`
  - `先别定性`
- 固定短指令
  - `先证据后判断`

解除控制也采用自然语言和短指令：

- `直接说结论`
- `你可以下判断了`
- `直接给判断`

### 4.2 内部控制意图

Phase 2 推荐新增一个轻量结果收口意图：

- `result_mode`

Phase 2 先只支持一个模式值：

- `evidence_first`

解除时将该模式清空，而不是引入额外复杂状态机。

## 5. 会话状态设计

Phase 2 继续挂在现有会话状态和 `AgentLoop` 周边，不引入新的 workflow engine。

建议新增最少状态：

- `workflow_result_mode: str | None`
- `workflow_result_mode_reason: str | None`
- `workflow_last_control_input: str | None`

约束如下：

- `workflow_result_mode="evidence_first"`：后续结果收口优先走证据结构
- `workflow_result_mode_reason`：记录简短来源，便于回显和审计
- 用户显式放行后清空 `workflow_result_mode` 及其附属原因
- 不清空已有证据、不回滚已有调查上下文

## 6. 回复分级

`evidence_first` 模式只约束“怎么对用户表达”，不约束“怎么调查”。

### 6.1 默认收口结构

结果回复建议按以下顺序组织，允许缺省，但顺序尽量稳定：

- 已确认事实
- 关键证据
- 未确认点或风险点
- 下一步建议

### 6.2 低置信度倾向

当当前证据已经明显指向某个方向时，允许额外补一段 `当前倾向`，但必须采用降级措辞，例如：

- `当前更像是 ...`
- `现有证据更偏向 ...`
- `目前更怀疑 ...`

### 6.3 强结论限制

在用户未显式放行前：

- 不允许把判断表达成 `根因已确认`
- 不允许把未验证前提上的修复建议表达成最终结论
- 如需建议动作，应表述为 `建议先验证 X，再决定是否执行 Y`

## 7. Loop 接入

Phase 2 的接入点应放在“自然语言结果输出”层，而不是工具调用层。

### 7.1 控制识别层

- 识别进入 `evidence_first` 模式的表达
- 识别解除 `evidence_first` 模式的表达
- 将控制写入 session metadata

### 7.2 运行时上下文层

- 在构建回复上下文时注入当前为 `evidence_first` 模式
- 明确该模式只影响结果收口，不影响调查动作选择

### 7.3 输出约束层

- 在生成阶段总结、调查结论或最终自然语言回复前检查 `workflow_result_mode`
- 当模式为 `evidence_first` 时，优先按证据结构收口
- 若出现强结论措辞，则降级成 `当前倾向`

## 8. 用户体验

控制反馈继续保持“驾驶舱确认”风格，而不是长篇聊天解释。

### 8.1 控制确认

示例：

- `后续先按证据收口；如果判断还不够稳，我会先列证据和未确认点。`
- `当前先不给定性结论；若证据已较强，我会补充一个低置信度倾向。`

### 8.2 解除确认

示例：

- `已解除证据优先收口；后续可直接给出判断。`

### 8.3 控制后的调查衔接

示例：

- `调查方式不变；我只会把结果先按证据和未确认点收口。`
- `如果现有证据已经足够强，我会补充当前倾向，但不会直接当作已确认根因。`

## 9. 测试边界

Phase 2 至少需要覆盖以下行为：

- `先别急着下结论`、`先给证据再说判断` 能识别成 `evidence_first`
- `直接说结论`、`你可以下判断了` 能解除该模式
- 模式写入 session metadata，后续 turn 继续生效
- 解除后状态被清除，不影响其他 workflow 控制
- 开启 `evidence_first` 后，调查工具选择和调查推进不应被截断
- `evidence_first` 下，回复优先呈现事实、证据、未确认点、下一步
- 当模型想输出强结论时，应被降级为 `当前倾向`
- 普通聊天或普通排障请求不能被误识别为结果收口控制
- 既有 inspection、report、case 流程不应被破坏

## 10. 非目标

本阶段明确不做：

- 证据置信度评分模型
- 任意结果模板编排器
- 新的报告产物工作流
- 结论审批系统
- 自动修复闭环

## 11. 推荐结论

Phase 2 推荐采用“证据优先的软门控收口模式”。

即：

- 新增轻量 `result_mode=evidence_first`
- 只约束结果收口，不限制调查动作
- 允许给低置信度倾向，但不允许在未放行前给出已确认根因式结论
- 继续沿用最小状态、最小侵入、最小行为面的设计原则

这样可以在不削弱排障能力的前提下，降低过早定性的风险，并为后续更强的结果产物化能力预留接口。
