# 排障能力优先级设计

## 1. 目标

明确为仓库级 agent 行为约束：本项目的第一目标是构建强大的排障能力。

该约束用于指导后续设计和实现取舍，避免项目在交互、展示、流程控制等增强上偏离主线，导致排障深度、证据质量或调查闭环被削弱。

## 2. 背景

当前项目已明显从通用 `nanobot` fork 演进为面向 HCI 场景的垂直排障助手 HCIGuard。

项目已有的主要差异化能力包括：

- 调查优先的排障链路
- 目标感知执行（`local` / `user@host[:port]`）
- 只读优先与审批机制
- 命令审计
- 案例沉淀与巡检报告

随着后续计划逐步涉及更强的工作流控制、交互反馈、展示层和文档表达，仓库需要一条更硬的优先级规则来约束 agent 的行为。

## 3. 设计原则

新增的仓库约束应满足以下原则：

- 清晰：一句话能看懂项目第一目标是什么
- 可执行：不是口号，而是能约束后续取舍
- 可落地：直接放进 `AGENTS.md`，对后续 agent 工作生效
- 不夸大：强调“排障能力优先”，但不否定交互和产品化增强的价值

## 4. 设计方案

### 4.1 主落点

将规则放入仓库根目录 `AGENTS.md`，新增单独章节：

`## Agent Priority`

建议文案如下：

```md
## Agent Priority
- 本项目的第一目标是构建强大的排障能力。
- 任何交互设计、工作流控制、展示优化、文档表达或辅助能力，都不应削弱排障深度、证据质量和调查闭环。
- 当“更强可控性 / 更强展示性 / 更强产品感”和“更强排障能力”发生冲突时，优先保证排障能力。
- 默认优先增强调查能力、证据收集能力、目标感知执行能力和排障结论质量，而不是优先增强表层交互。
```

### 4.2 可选对外补充

若需要同步到对外定位，可在 `README.md` 和 `README.zh-CN.md` 的定位段落里补一条更简短的表达。

英文建议：

```md
HCIGuard's first priority is strong troubleshooting capability. Interaction, workflow, and presentation improvements should strengthen troubleshooting depth rather than distract from it.
```

中文建议：

```md
HCIGuard 的第一优先级是强大的排障能力。交互、流程和展示层的增强，应服务于排障深度，而不是稀释它。
```

但该部分属于可选增强，本次最小落地只要求 `AGENTS.md` 生效。

## 5. 非目标

本次不做以下事情：

- 不同时引入新的工作流控制能力
- 不修改 `AgentLoop` 实现
- 不同步重写 PRD 或技术设计文档
- 不把该约束扩展成完整的项目价值观章节

## 6. 预期效果

落地后，后续在以下问题上会有更稳定的默认判断：

- 控制能力是否会削弱排障能力
- 交互反馈是否过度重视“产品感”
- 展示层增强是否偏离核心排障目标
- 功能排期是否优先调查能力而非表层包装
