# HCIGuard V1.1 Issue Template

Use this template to open execution issues for `V1.1: Multi-Target Foundations`.

## Usage

1. Copy one template block per issue.
2. Replace placeholders in `<>`.
3. Keep scope small: one module task per issue.

## Generic Issue Template

```md
Title: [V1.1][<module>] <short task name>

## Goal
<What this issue delivers and why it matters in V1.1>

## Scope
- In:
  - <item 1>
  - <item 2>
- Out:
  - <item 1>

## Implementation Notes
- <key design or interface notes>
- <data model / API / command impacts>

## Acceptance Criteria
- [ ] <criterion 1>
- [ ] <criterion 2>
- [ ] <criterion 3>

## Test Plan
- Unit:
  - <tests to add/update>
- Integration:
  - <scenario to run>
- Regression:
  - <existing test path to verify>

## Risks / Edge Cases
- <risk 1 + mitigation>
- <risk 2 + mitigation>

## Definition of Done
- [ ] Code merged
- [ ] Tests added/updated and passing in CI
- [ ] Docs/config examples updated
- [ ] Audit/report behavior verified (if touched)
```

## Ready-to-Use Issue Seeds (V1.1)

### 1) Config model

```md
Title: [V1.1][config] Add multi-target grouping and labeling schema

## Goal
Support `targets`, `groups`, and `labels` in config so multi-target requests are explicit and validatable.

## Scope
- In:
  - Add schema fields for target grouping/tagging.
  - Validate references between groups and target definitions.
- Out:
  - Runtime correlation logic.

## Acceptance Criteria
- [ ] Invalid references fail fast with clear validation messages.
- [ ] Valid config supports at least three targets in one group.
- [ ] Backward compatibility with current single-target config is preserved.
```

### 2) Target resolver

```md
Title: [V1.1][resolver] Resolve target sets from group/tag filters

## Goal
Build deterministic resolution from request scope (`group`, `label`, explicit list) to final target set.

## Acceptance Criteria
- [ ] Same input always resolves to the same ordered target set.
- [ ] Missing/invalid selectors return actionable errors.
- [ ] Resolution result is reusable by inspection and troubleshooting paths.
```

### 3) Inspection runner

```md
Title: [V1.1][inspection] Run one profile across N targets

## Goal
Execute one inspection profile on all resolved targets and return per-target outcomes.

## Acceptance Criteria
- [ ] One command can run inspection across multiple targets.
- [ ] Output includes per-target status (`ok`, `failed`, `skipped`).
- [ ] Partial failures do not hide successful target outputs.
```

### 4) Troubleshooting tool context

```md
Title: [V1.1][tools] Carry target identity through troubleshooting outputs

## Goal
Ensure tool outputs always identify where evidence came from.

## Acceptance Criteria
- [ ] Tool outputs include `target_id` and `target_host` for remote targets.
- [ ] Local runs remain readable and backward compatible.
- [ ] Mixed-target runs are distinguishable in a single response.
```

### 5) Report and case pipeline

```md
Title: [V1.1][report-case] Group evidence by target and incident window

## Goal
Produce reports and case records that preserve per-target evidence boundaries.

## Acceptance Criteria
- [ ] Reports have per-target sections plus a shared summary.
- [ ] Case entries link to all target-specific artifacts.
- [ ] Time window is explicit in report and case metadata.
```

### 6) Audit pipeline

```md
Title: [V1.1][audit] Record target metadata for every executed action

## Goal
Strengthen traceability for multi-target runs.

## Acceptance Criteria
- [ ] Every audit entry includes `target`, `executor`, `command`, `timestamp`, `result`.
- [ ] Per-target action history can be reconstructed from audit logs.
- [ ] Existing audit readers do not break.
```

### 7) Channel UX

```md
Title: [V1.1][ux] Expose target scope in CLI and IM interactions

## Goal
Show users exactly which targets are in scope before and after execution.

## Acceptance Criteria
- [ ] Pre-run message shows resolved target scope.
- [ ] Post-run summary shows success/failure by target.
- [ ] Approval prompts include target context.
```

### 8) Regression coverage

```md
Title: [V1.1][tests] Add multi-target regression suite

## Goal
Protect the V1.1 critical path in CI.

## Acceptance Criteria
- [ ] Tests cover config, resolver, runner, report, and audit paths.
- [ ] CI includes dedicated V1.1 regression entries.
- [ ] Failures clearly indicate target-specific vs global regressions.
```
