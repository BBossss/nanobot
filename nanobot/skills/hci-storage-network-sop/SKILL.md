# HCI Storage and Network SOP

适用于存储异常、网络异常、节点健康异常等专项排障。

## 使用方式

先判断故障类型，再参考对应专项资料：

- `references/storage.md`
- `references/network.md`
- `references/node-health.md`

## 工作原则

- 先判断影响范围，再采集日志和状态
- 先只读检查，再给出修复建议
- 先确认当前事实，再引用历史案例

## 远程专项检查规则

当存储、网络、节点健康问题发生在远程 HCI 主机上时：

- 先确认目标主机和问题范围，再开始远程采样
- 需要远程执行只读命令时，优先使用带 `target` 的 `exec`
- 不要直接拼写 `ssh ...` 原始命令字符串
- 优先读取远程日志、服务状态、系统状态，不先做写操作
- 关键证据必须带目标主机标识
- 若多个节点都异常，先分别列证据，再做对比，不要把多台机器结果混成一条结论

远程执行约束：

- `command` 只放目标主机上实际执行的只读命令
- SSH 目标主机、用户、端口通过 `target` 表达
- 如果是 CLI 场景且认证失败，可以接受一次隐藏输入的 SSH 密码重试
- 不在 IM 场景中默认依赖密码型 SSH 交互

远程专项排查优先顺序：

1. 目标主机的症状和影响范围
2. 目标主机的关键日志与错误关键词
3. 目标主机的服务/进程/磁盘/网络状态
4. 与其他节点或控制机的差异点

## 输出要求

- 当前症状
- 关键证据
- 可能根因
- 下一步检查或处理动作

远程专项输出中应额外明确：

- 证据来自哪台主机
- 是否需要与其他节点对照
- 当前建议是继续只读采证还是需要人工变更确认
